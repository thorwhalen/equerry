Research theme: executive briefs and attention triage from many sources — how to produce a "what needs me" brief on a cadence (daily, or scheduled per weekday) from coding-session activity, GitHub, Slack, email and chat exports, for a principal who reads on a phone.

Cover: how products do it today (ChatGPT Pulse, Gemini's daily brief in Gmail and Workspace, Superhuman and Shortwave AI summaries, Slack AI recaps and channel digests, GitHub Copilot and GitHub notification digests, Notion Mail, Fyxer, Motion/Reclaim daily plans) and what users say works or fails; the research on information triage and alert fatigue (what fraction of items should be surfaced, near-miss learning, habituation), on executive briefing formats (BLUF, one-page briefs, exception reporting), and on prioritisation models usable by a model (urgency × ownership × reversibility, "needs you" classes); the mechanics: source adapters, watermarks so nothing is shown twice, dedup across sources (the same thread via GitHub and Slack), ranking, a daily cap, a feedback loop (seen / later / done), rendering for a phone and for text-to-speech, and scheduling with local time zones and per-weekday cadences. Deliverable: a recommended brief schema (sections, item fields, caps), the pipeline shape (ingest → normalise → rank → compose → render → deliver → feedback), evaluation metrics (precision of "needs you", override rate), and standard terminology. Note that an overview pipeline for sources → extract → compose → render already exists in the owner's fleet and must be reused, not redesigned; focus on what it lacks (multi-source triage, cadence, feedback). Also anything important I did not ask.
