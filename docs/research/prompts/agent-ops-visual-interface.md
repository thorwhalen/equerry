Research theme: the visual interface for operating a fleet of agents ("mission control" for one principal), phone-first, independent of any voice layer.

Cover: how existing products present many agents and their work to one operator: OpenClaw's control UI and the community "mission control" dashboards, Paperclip's org-chart view, OpenHands, Devin, Cursor background agents, Codex, Claude Code on the web and Remote Control, Factory, Linear and GitHub Projects used as agent desks, Kanban boards for agents; the information architecture patterns (feed vs board vs inbox vs chat; approval cards; exception lists; a "needs you" lane; drill-down from a line to the transcript), notification design on phones, and what the HCI literature says about supervisory control of many automated workers (levels of automation, situation awareness, alarm management, Bainbridge's ironies of automation). Deliverable: a recommended information architecture for a phone-first desk (screens, the one list that matters, what each tap does, how voice attaches later as an input/output adapter), the shape of the data it needs from the organisation layer (so the layer is designed interface-agnostic), a comparison table of the products with licence and verdict (study / borrow pattern / avoid), and standard terminology. Also anything important I did not ask.
