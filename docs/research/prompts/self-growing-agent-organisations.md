Research theme: organisations of AI agents that grow themselves — one experienced generalist per domain (legal, people, marketing, business development, finance, research, engineering) who, on each ask, first judges whether it has the research, skills and sub-agents to do the job expertly, and if not either trains (sharpens or extends an existing agent primitive: a skill, a reference file, a prompt, a checklist) or hires (creates a new primitive: a sub-agent, a skill, a tool), then does the work. For a framework whose agents are Claude Code sessions and sub-agents, whose primitives are SKILL.md files, sub-agent definitions, reference folders and MCP tools, and whose principal is one person.

Cover: prior art on self-extending agent systems and skill libraries (Voyager's skill library, SkillWeaver, agents that write tools for themselves, "learn-by-interaction" systems, Anthropic skills and Claude Code sub-agents, OpenAI Agents SDK handoffs, CrewAI hierarchical process, MetaGPT SOP roles, ChatDev, Agency Swarm, Paperclip's company-of-agents model, Gas Town, OpenClaw's agent/skill ecosystem); the "company of agents" pattern and its published failure modes (role play without competence, agents that invent process, unbounded agent creation, cost blow-ups); governance of self-modification: who may create or change a primitive, review before use, versioning and provenance of agent-written skills, evaluation gates (does the new primitive actually improve the job?), the distinction between a reusable mechanic and an instance tuned to one principal; how to measure a domain expert's coverage of an ask (coverage check before acting, as in retrieval abstention) and when to escalate to a human professional instead of hiring an agent; cost control (one generalist on a strong model vs many specialists); the literature on generalist-vs-specialist agents and on prompt/skill specialisation versus fine-tuning. Deliverable: a comparison table of the systems, the recommended "assess, then train or hire, then act" protocol as a concrete checklist an agent can follow, the data each team should keep (a roster of primitives, a log of hires and trainings with the ask that caused each, the coverage verdicts), the gates, the standard terminology, and the minimum viable version. Also anything important I did not ask.
